// Conjunto de deudas (creditos de un cliente o de toda la financiera). No se persiste.
// Composite: suma la deuda de sus hijos sin saber si son creditos o cuotas
public final class Cartera implements Deuda {

    private final List<Deuda> deudas;

    private Cartera(List<Deuda> deudas) {
        this.deudas = deudas;
    }

    public static Cartera de(List<? extends Deuda> deudas) {
        return new Cartera(List.copyOf(deudas));
    }

    public BigDecimal saldo() {
        return sumar(Deuda::saldo);
    }

    public BigDecimal montoVencido() {
        return sumar(Deuda::montoVencido);
    }

    private BigDecimal sumar(Function<Deuda, BigDecimal> monto) {
        return deudas.stream()
            .map(monto)
            .reduce(BigDecimal.ZERO, BigDecimal::add);
    }
}

M12. Decorator: cargos sobre la cuota expansión del dominio

Commits 4eab370, 54cd991; 3fc5b9d lo muda a CondicionesDeCredito. Tabla nueva credito_cargos.

Patrón
Decorator (GoF, estructural): agrega responsabilidades a un objeto por composición, en vez de una subclase por combinación.
Problema (código antes)

Un préstamo real suma cargos opcionales (seguro de vida, gastos). Con herencia: una subclase por plan × combinación.

backend/src/main/java/com/uade/tpejemplo/model/Credito.java · V3 (tag v3)

    }
Solución (código después)

Cada cargo envuelve el cálculo y suma lo suyo; CondicionesDeCredito arma la pila (M17).

backend/src/main/java/com/uade/tpejemplo/model/CondicionesDeCredito.java · V4 (iteracion4)
    // Strategy: el contexto delega el cálculo de la cuota en la estrategia elegida al otorgar (no cambia después)
    // Decorator: cada cargo del credito envuelve a la estrategia y le suma lo suyo
    private CalculoDeCuota calculo() {
        CalculoDeCuota calculo = tipoPlan.calculo();
        for (TipoCargo cargo : cargos) {
            calculo = cargo.aplicarSobre(calculo);

    }

// Cargo que se suma a la cuota sin tocar el sistema de amortizacion.
// Decorator: envuelve un CalculoDeCuota, delega en el y le suma su cargo
public abstract class CargoSobreCuota implements CalculoDeCuota {

    private final CalculoDeCuota envuelto;

    protected CargoSobreCuota(CalculoDeCuota envuelto) {
        this.envuelto = envuelto;
    }

    @Override
    public BigDecimal importeCuota(BigDecimal capital, BigDecimal tasaInteres, int cantidadCuotas) {
        return envuelto.importeCuota(capital, tasaInteres, cantidadCuotas).add(cargo(capital, cantidadCuotas));
    }

    protected abstract BigDecimal cargo(BigDecimal capital, int cantidadCuotas);
}

// Cargos opcionales que se eligen al otorgar un credito. Se guarda el nombre

Pregunta trampa: “¿No es otra Strategy?”
No: Strategy elige un algoritmo; los decoradores se apilan sobre él.
Pregunta trampa: “¿Para qué está TipoCargo?”
Un decorador no se guarda ni viaja en el JSON: se guarda el nombre del cargo (credito_cargos) y con él se rearma la pila. Cada constante sobrescribe aplicarSobre con su decorador: Polymorphism en vez de un switch por tipo.

M19. Interés simple real y tasa mensual única corrección de dominio

Commits 9c3f79d, 9ff9ed8 (textos del panel).

Patrón

Problema (código antes)

Error que viene de V3: InteresSimple cobraba C · (1 + i), lo mismo en 6 o 24 cuotas: un recargo fijo, no interés. Y tasaInteres tenía dos unidades: % total en simple, % mensual en francés.

        BigDecimal coeficiente = BigDecimal.ONE.add(tasaInteres.divide(CIEN, 4, RoundingMode.HALF_UP));

Solución (código después)

Interés simple real: total = C · (1 + i · n), con i mensual. Las dos estrategias reciben la misma tasa mensual.

backend/src/main/java/com/uade/tpejemplo/model/plan/InteresSimple.java · V4 (iteracion4)

// y n = cantidad de cuotas. 10.000 al 3% mensual se devuelven 11.800 en 6 cuotas y 17.200 en 24.

    private BigDecimal totalADevolver(BigDecimal capital, BigDecimal tasaInteres, int cantidadCuotas) {
        BigDecimal interes = tasaInteres.divide(CIEN, 4, RoundingMode.HALF_UP).multiply(BigDecimal.valueOf(cantidadCuotas));
        return capital.multiply(BigDecimal.ONE.add(interes)).setScale(2, RoundingMode.HALF_UP);
    }

Por qué
Corrección de dominio: el interés simple depende del plazo. Lenguaje ubicuo: un atributo no cambia de unidad según otro. La interfaz CalculoDeCuota no cambia: solo una estrategia concreta (OCP).

Solución (código después)

Única fuente: Cuota.importe, el hecho histórico. Credito suma sus cuotas para el total, igual que saldo(). Las condiciones la calculan solo para generar el plan (package-private).

backend/src/main/java/com/uade/tpejemplo/model/Credito.java · V4 (iteracion4)

Por qué
Composite: el total es una suma más sobre las hojas. Information Expert: la cuota conoce su importe. Se guardan hechos, se derivan totales.
